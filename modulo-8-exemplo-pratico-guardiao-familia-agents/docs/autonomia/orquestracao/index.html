1. Onde cada tecnologia começa

Leia de cima para baixo: a orquestração “desce” até o board; observabilidade “sobe” em paralelo.

Entrada
CLI / Cursor / demo
scripts/langgraph_run.py · scripts/demo_apresentacao.py · chat Cursor com MCP guardiao-familia-agents. Env: lib/env_load.ensure_env() (OpenRouter, LangSmith, SSL).
Orquestração
LangGraph (langgraph_app/graph.py) — StateGraph com loop até Done / HITL / max_steps. Flag GUARDIAO_ORCHESTRATOR=langgraph. Pasta crew/ = env + output runtime (não orquestra).
Decisão LLM
OpenRouter via langchain_openai.ChatOpenAI (langgraph_app/llm.py) + lib/model_tier.select_model (Fase A). Purpose: route (sem LLM), summarize, implement_*, review.
Tools
MCP guardiao_mcp/ (Cursor) ou tools_bridge in-process no grafo (mesmas APIs). Escrita default dry_run=true; dispatch só com GUARDIAO_MCP_ALLOW_DISPATCH=1.
Domínio
Gateway lib/gateway.py + board, HITL, handoff, router, react_policy. Project #2 via gh quando autenticado.
Código
Cursor Automation / SDK (GUARDIAO_CURSOR_MODEL) — implementação real nos repos; na demo/dry_run o nó implement só resume / artefato local.
Obs.
LangSmith (Fase D) + crew/output/observability/tasks/*.html (ReAct + tokens) + dataset estático evals/.

3. Detalhe de cada etapa do Kanban

MVP Fase C compacta alguns Status intermediários (salta In Code Review / In Test via approve_review / test_passed).

1 Todo → In Progress orchestrator / creator LLM decide claim

Nós: route → load_context → decide → apply

Tecnologia: policy sugere claim; LLM preenche summary/rationale (purpose=implement_low|high (SOS → high). Apply simula (dry_run) ou chama gateway.

MCP equivalente: emit_status_event(event=claim), pick_task_tool, resolve_agent_for_board_event

Agente: role do CSV (TASK_AGENT_MAP) — ex. frontend-mobile em T-P05-006.

2 In Progress → Ready for Code Review creator summarize open_pr

Nós: route → load_context → implement → apply

Tecnologia: nó implement (workspace demo ou só resumo); LLM purpose=summarize (mini). Evento forçado open_pr.

Código real: fora do grafo — Cursor dispatch / skill do agente (agents/*.agent.md quando não é dry_run acadêmico.

MCP: write_handoff_tool, append_task_action_tool, dispatch_job_tool (gated), emit_status_event(open_pr)

3 Ready for Code Review → Ready for Test *-reviewer review approve_review

Nós: review → apply

Tecnologia: structured output ReviewVerdict; modelo high se risco / purpose review. Approve → approve_review; senão request_changes (volta In Progress).

Agente doc: agents/reviewers/*-reviewer.agent.md

4 Ready for Test → In Pull Request qa-gate test_passed

Nós: qa → apply

Tecnologia: gate tipado (MVP sem LLM). Evento test_passed. Em operação plena existiria start_test / test_failed_bug.

5 In Pull Request → Done devops-cicd + humano HITL merge_pr

Nós: hitl → apply

Modes:

  • dry_run — simula Done
  • demo — gateway com force_hitl_approved
  • live — pode ficar hitl_pending; humano approve_hitl (MCP/dashboard)

Não há Status “Awaiting Human” no Kanban — a pausa vive em hitl_queue.

7. Modes de execução

LLM + simulação de Status (não grava board). Ideal para banca local e evals. Histórico HTML ainda registra tokens/modelo. Comando: python scripts/langgraph_run.py --task T-P05-006 --mode dry_run --from-zero
Emite gateway de verdade; merge com force_hitl_approved. Dashboard live reflete Status. Bom smoke “quase produção”.
Emite gateway; merge pode pausar em HITL. Aprovar via MCP approve_hitl ou fluxo operacional. Não pular HITL em produção acadêmica/piloto.
